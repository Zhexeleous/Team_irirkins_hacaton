# Token-Efficient SDD



## Быстрый запуск

### 1. Установите зависимости

Нужны Git, Node.js 22.20 или новее и доступная в OpenCode модель. Команды ниже рассчитаны на OpenCode 2.3.2 и OpenSpec 2.1.1. Обе версии можно установить через npm.

```sh
npm install -g @opencode/cli@2.3.2 @fission-ai/openspec@2.1.1
opencode models
```


### 2. Подготовьте целевой проект

Клонируйте этот репозиторий плагина отдельно от проекта, над которым будет работать агент. Подставьте URL из кнопки **Code** на GitHub. Если плагин уже скачан, укажите его путь в `PLUGIN_DIR`.

```sh
git clone "URL_РЕПОЗИТОРИЯ_ПЛАГИНА" "$HOME/sdd-optimizer"
PLUGIN_DIR="$HOME/sdd-optimizer"
cd "/path/to/your-project"
```

Все следующие команды запускайте из корня **целевого проекта**. В нём должно быть открытое изменение с файлом `openspec/changes/<id>/tasks.md`. Раннер берёт оттуда задачи с отметкой `- [ ]`. Если изменение уже подготовлено и OpenSpec настроен для OpenCode, переходите к следующему шагу.

Если интеграции с OpenCode ещё нет, настройте её из корня целевого проекта.

```sh
openspec init --tools opencode --scope project --profile core --no-animation
```

Если изменения ещё нет, откройте `opencode` из той же папки и используйте навык `openspec-propose`. Попросите подготовить изменение с идентификатором `add-feature`, опишите нужную фичу и попросите остановиться после подготовки артефактов. Проверьте, что появился `openspec/changes/add-feature/tasks.md` с невыполненными задачами.

### 3. Проверьте и запустите

Проверьте, что путь `.opencode/plugins/sdd-test-log-summary.js` в целевом проекте свободен. Враппер копирует туда плагин на время запуска и затем удаляет файл. Если путь уже занят, освободите его в рабочей копии, которую используете для прогона.

Подставьте идентификатор своего изменения и модель из вывода `opencode models`. В примере указан Big Pickle.

```sh
CHANGE_ID=add-feature
MODEL=opencode/big-pickle
PROMPT="Используй openspec-apply-change для изменения $CHANGE_ID. Выполни задачи из openspec/changes/$CHANGE_ID/tasks.md. Запускай проверки проекта и отмечай выполненные задачи в tasks.md."

node "$PLUGIN_DIR/sdd-wrapper.mjs" "$PROMPT" \
  --change "$CHANGE_ID" --model "$MODEL" --dry-run
```

`--dry-run` печатает список задач и помечает следующую без вызова модели. Если работает фоновый сервис OpenCode, перед обычным запуском завершите его активные сессии и остановите сервис командой `opencode service stop`. Так новый процесс получит настройки от раннера.

Раннер автоматически разрешает инструменты OpenCode в обоих режимах. Агент может менять файлы проекта, поэтому первый прогон лучше делать в отдельной ветке или рабочей копии.

```sh
node "$PLUGIN_DIR/sdd-wrapper.mjs" "$PROMPT" \
  --change "$CHANGE_ID" --model "$MODEL"
```

Для пробного запуска с одной задачей добавьте `--max-tasks 1`. При следующем запуске раннер продолжит с первого незакрытого пункта.

## Как работает

- [`sdd-wrapper.mjs`](sdd-wrapper.mjs) подключает модуль логов к целевому проекту на время прогона и передаёт аргументы раннеру.
- [`plugin/isolation/sdd-runner.mjs`](plugin/isolation/sdd-runner.mjs) открывает сессии OpenCode по очереди в одной рабочей копии и переходит к следующей задаче после отметки `[x]`. В `.sdd-opt/handoff.md` записывает названия задач и список добавленных или изменённых файлов.
- [`plugin/test-logs/index.js`](plugin/test-logs/index.js) распознаёт длинный вывод `pytest` и заменяет его сводкой с кодом завершения, итогом тестов и ключевыми строками ошибки. Полный вывод доступен по пути из поля `Full log:`.

Раннер подходит для разных языков и сборщиков. Агент выполняет команды самого проекта. Сводки поддерживают `pytest`, для остальных команд действует стандартная обработка вывода OpenCode.

## Аргументы

| Аргумент | Что делает |
| --- | --- |
| `"<промпт>"` | Обязательный текст задачи для OpenCode. |
| `--change <id>` | Выбирает изменение по имени папки в `openspec/changes/`. Без флага берёт последнее изменённое `tasks.md`, отдавая приоритет изменениям с открытыми задачами. |
| `--model <провайдер/модель>` | Выбирает модель. По умолчанию используется модель из настроек OpenCode. |
| `--max-tasks <N>` | Ограничивает количество задач за запуск в оптимизированном режиме. |
| `--dry-run` | Показывает выбранное изменение и план запуска без обращения к модели. |
| `--baseline` | Запускает исходный промпт одной сессией, без разбиения по задачам и подключения модуля логов враппером. |
| `--no-isolation` | Отключает изоляцию окон. |
| `--no-reduction` | Отключает плагин reduction. |
| `--no-test-logs` | Отключает плагин сжатия логов pytest. |

## Сравнение с baseline

Для A/B возьмите две рабочие копии проекта с одинаковыми исходниками и артефактами OpenSpec. Выполните обычную команду в первой копии, а затем запустите тот же промпт с той же моделью и `--baseline` во второй.

```sh
node "$PLUGIN_DIR/sdd-wrapper.mjs" "$PROMPT" \
  --change "$CHANGE_ID" --model "$MODEL" --baseline
```

Раннер сохраняет результаты в целевом проекте.

| Путь | Содержимое |
| --- | --- |
| `.sdd-opt/metrics-<id>.json` | Метрики оптимизированного прогона по задачам и в сумме. |
| `.sdd-opt/baseline-metrics-<id>.json` | Метрики базовой сессии и разбивка по шагам. |
| `.sdd-opt/logs/` | События OpenCode для каждого прогона. |
| `.sdd-opt/handoff.md` | Журнал для передачи контекста между задачами. |

Метрики содержат входные и выходные токены, чтение и запись кэша. Для сопоставимого замера проверьте в обеих копиях выполнение одного и того же списка задач и результаты тестов. Если базовый прогон показывает `Шагов LLM: 0`, проверьте его JSONL-файл на ошибки OpenCode.

## Проект для прогона

Для проверки использовали [koolkhel/llmwiki](https://github.com/koolkhel/llmwiki), открытый Python-проект для ведения вики.

```sh
git clone https://github.com/koolkhel/llmwiki.git
cd llmwiki
```

В эксперименте реализовывали `vault-upgrade` на [коммите до реализации](https://github.com/koolkhel/llmwiki/commit/b9b9b0d7674d9a828501c34e894f92e3d01f1500) с артефактами OpenSpec из [коммита с реализацией](https://github.com/koolkhel/llmwiki/commit/3922c85c704e0d38e85ef59c4e4d1674ea60b379). В актуальной версии репозитория это изменение уже в архиве. Чтобы попробовать плагин на скачанном проекте, подготовьте новое изменение и запустите его по инструкции выше.
